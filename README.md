# POS — Restaurant Billing App

Offline-first billing/POS app for small restaurants. Runs standalone on a single
device with zero backend; optionally syncs to Firebase when multiple devices
need to share data.

## Stack

- **App**: React Native (Expo, SDK 57) + TypeScript + expo-router
- **Local DB**: SQLite via `expo-sqlite` + Drizzle ORM, with a generated migrations system
- **State**: Zustand
- **Auth**: PIN-based, per staff member, tied to role (owner/admin/cashier)
- **Sync (optional, Phase 7)**: manual "Sync Now" push of a local change queue to Firebase —
  chosen over a custom Node/Postgres backend so multi-device sync needs no self-hosted server
- **Printing**: ESC/POS over Bluetooth (Phase 4)

## Getting started

```bash
npm install
npm run android   # or: npm run ios / npm run web (web has reduced SQLite support, see below)
```

On first launch the app bootstraps a default restaurant and an **Owner** account with
PIN `1234` (see `src/db/seed.ts` — change this from Settings once that screen exists).

## Project structure

```
app/                      expo-router routes
  (auth)/login.tsx         PIN pad login
  (app)/                   tab navigator, requires auth
    orders/  tables/  menu/  reports/  settings/
src/
  db/
    schema/                Drizzle table definitions, one file per domain
    migrations/             generated by `npm run db:generate` — commit these
    client.ts               opens the SQLite db, wires up Drizzle
    seed.ts                 first-run bootstrap data
  features/                 business logic by domain (auth, billing, tax, sync, ...)
  store/                    Zustand stores
  components/, lib/, types/, constants/
```

## Data model

Defined in `src/db/schema/*.ts`. Summary:

- `restaurants`, `users` — one business, staff with PIN auth and a role
- `categories`, `menuItems`, `modifierGroups`, `modifiers`, `menuItemModifierGroups`,
  `comboDeals`, `comboDealItems` — menu structure; modifiers attach to items without duplication
- `taxRules`, `taxComponents` — a named tax slab made of one or more components (e.g.
  CGST 2.5% + SGST 2.5%), so region-specific splits print correctly without being India-hardcoded
- `diningTables`, `orders`, `orderItems`, `orderItemModifiers` — order/bill lifecycle;
  item name/price are snapshotted at add-time so historical bills survive menu edits
- `discounts`, `payments` — bill- or item-level discounts, and split payments across modes
- `auditLogs` — append-only log of edits/voids/overrides (Phase 6)
- `syncQueue` — change log consumed by the Phase 7 Firebase sync

## Database migrations

Schema changes go in `src/db/schema/`, then:

```bash
npm run db:generate   # regenerates src/db/migrations/*.sql + migrations.js
```

Migrations run automatically on app start via `useMigrations` in `app/_layout.tsx`.

## Known limitation: web platform

`expo-sqlite`'s web backend needs cross-origin-isolation headers (`SharedArrayBuffer`) that
aren't configured, so `npm run web` will fail to open the database. This isn't a target
platform for this app (Android/iOS tablets are) — Android/iOS builds use the native SQLite
binding and are unaffected. Fixing web support is out of scope unless a browser-based build
becomes a real requirement.
